- `v0.11.23: Добавить быстрые настройки одноразовых уведомлений` — заменить кнопку подключения в сообщении бота на переключатель статуса для уже подключённых пользователей; открывать настройки уведомлений напрямую и синхронизировать подпись кнопки при изменении настройки.

- `v0.11.20: Упростить оплату через Tribute` — в окне оплаты выбрать Tribute среди двух платёжных сервисов, оставить второй вариант заглушкой, убрать переключатель разовой оплаты и автопродления для подписок; перед переходом в Tribute пользователь выбирает сервис и принимает оферту, подписки продлеваются автоматически, пакеты остаются разовыми.

- `v0.11.18: Добавить цены групп в Telegram Stars` — показать цены тарифов на 3, 10 и 20 групп в Stars рядом с рублёвыми ценами; значения рассчитаны по принятому в приложении соотношению 1 ⭐ ≈ 1,6 ₽.

- `v0.11.17: Подключить Stars для безлимита на месяц` — при оплате месячного безлимита открывается Telegram-ссылка Tribute для оплаты Stars; другие тарифы и товары продолжают открываться по веб-ссылкам Tribute.

- `v0.11.16: Пересобрать товары Tribute на базе v0.11.7` — подключить девять товаров Tribute к исходной кодовой базе v0.11.7; после вебхука активируется выбранный безлимит, пакет уведомлений или групповой лимит.

- `v0.11.15: Подключить товары Tribute` — добавить товары на 1, 6 и 12 месяцев безлимита, пакеты на 100, 300 и 500 уведомлений и групповые тарифы на 3, 10 и 20 групп. Tribute открывает страницу конкретного товара; после подтверждения вебхуком безлимит, остаток уведомлений или групповой лимит отображаются в профиле.

- `v0.11.14: Скрывать обычные сообщения в ответах` — новая проверка уведомлений скрывает обычные сообщения, сохраняет уведомления об удалении и редактировании согласно настройкам и разрешает новые только для входящих одноразовых. В обработке цитат обычными считаются медиа с положительным `message_id` без признаков одноразовости; остальные кандидаты сохраняются.

- `v0.11.13: Отсеивать обычное медиа в ответах` — в цепочке ответа скрываются сообщения с положительным `message_id` и без признаков одноразовости; сообщения без достаточных метаданных могут остаться неоднозначными.

- `v0.11.12: Распознавать одноразовые сообщения без вложения` — входящее личное сообщение с `message_id = 0` распознаётся как одноразовое даже если Telegram не передал медиафайл; отсутствующее вложение восстановить нельзя.

- `v0.11.11: Скрывать обычные сообщения, на которые ответили` — обычные сообщения скрываются из архива и уведомлений; ответ на обычное сообщение не превращает его в одноразовое.

## Every production update

1. Use the next semantic version: `PATCH` for a fix, `MINOR` for a backward-compatible feature, and `MAJOR` for a breaking change or a change that needs a user action.
2. Commit the complete change directly to the Cloudflare-connected GitHub branch (`main`) with a title in this format:

   ```text
   v0.2.2: Show Telegram profile photos
   ```

   The version and short change description in this commit title are also the Cloudflare deployment title. Keep the colon; the configured deploy command uses the part before it as the version tag.
3. GitHub sends the new `main` commit to Cloudflare Workers Builds. It deploys the Worker and assets at the existing Worker URL, which is the URL opened by Telegram. Users see the new app when they open or reload it; no BotFather URL change is needed for normal app updates.
4. In Cloudflare, confirm the latest deployment shows the expected `vX.Y.Z: change` title and succeeded before announcing the release.

Cloudflare's production Deploy command must be:

```sh
npx wrangler deploy --env production --name spychau-bot --message "$(git log -1 --pretty=%s)" --tag "$(git log -1 --pretty=%s | cut -d: -f1)"
```

For a database schema change, add a new numbered SQL migration in `migrations/` and apply it to production before deploying code that depends on it. Never edit a migration already applied in production.

## Roll back application code

In Cloudflare, open **Workers & Pages → spychau-bot → Deployments**, select the known-good Worker version, and choose **Rollback**. Alternatively, use `npx wrangler rollback <VERSION_ID>` from a signed-in Wrangler project. Record the rollback in GitHub with a commit using a new version number so the source history matches production.

A Worker rollback restores code and configuration associated with that version. It does not undo D1 writes or schema migrations. Back up production data before risky migrations and use a new forward migration to repair production data/schema; do not assume rolling back Worker code reverses database changes.
